## Overview

This repository contains my submission for the Roblox take-home test.

The project is structured as a CMake project. The `CMakeLists.txt` and related configuration files were auto-generated by Visual Studio and are included only to support configuration and compilation.

The primary implementation is located in the `RobloxTakeHomeTest` folder.

## Project Structure

### `RobloxTakeHomeTest`

This folder contains the main source files:

* `Algorithms.h`
* `Algorithms.cpp`
* `Tests.cpp`

#### `Algorithms.h`

Contains the declarations for each algorithm, along with high-level descriptions of their purpose and approach.

The algorithms were written as self-contained functions with minimal supporting infrastructure. This led to fairly extensive lambda usage for helper operations that are specific to each implementation.

In a production codebase, I would separate the current responsibilities into clearer components, such as data representation, mathematical utilities, algorithm implementations, and testing. The current structure reflects the time constraints of the exercise rather than a preferred long-term architecture.

#### `Algorithms.cpp`

Contains the implementations of the approaches explored:

* a naive enumeration method;
* a bespoke exponent-space method;
* the standard three-pointer method;
* a predictive rank-counting method for very large sequence positions.

The implementations are intentionally independent so their correctness, performance, and trade-offs can be compared directly.

#### `Tests.cpp`

Provides a lightweight executable test and demonstration harness.

It:

* verifies known sequence values;
* cross-checks the implementations against one another;
* measures execution time over a range of inputs;
* writes timing data for plotting;
* prints the predicted four-billionth sequence entry.

Because third-party libraries were not permitted, and because of the available development time, I did not add a full testing framework such as Catch2. In production, I would use a proper unit-test suite with isolated test cases, edge-case coverage, and automated regression testing.

## Time Spent

The task took approximately six hours.

The first three solutions were completed after approximately four hours. Had I skipped the bespoke approach and gone directly to researching the known solution, the core problem could likely have been solved much more quickly.

I chose instead to spend the additional time exploring alternative approaches, validating the results, documenting the reasoning, and comparing performance. This was a deliberate trade-off in favour of completeness and rigor over producing only the shortest working solution.

## Building and Running

The project can be configured and built from a terminal using CMake.

From the repository root, run:

```bash
cmake -S . -B build
cmake --build build --config Release
```

Run the generated Tests executable to execute the correctness checks, print timing information, generate the timing data used by the plotting script, and print the predicted result for the four-billionth sequence entry.
